## 正文

### 一个大概率的场景

你让 agent 去做一件事，它说"好的，我开始做了"，然后开始调工具、跑命令、写文件。

你去倒了杯水，回来发现它停在某个问题上等你回答——**已经等了 17 分钟**。

或者更糟：它有个"目标"在自动续轮，你以为它在干活，其实它三轮之前就 blocked 了。

`[你的经历，一句话即可：例如"上周我把一个迁移任务丢给它，回来发现它在等我确认一个路径，白等了半小时。"]`

这不是模型能力问题。这是**界面问题**：它做了很多事，但没有一个地方告诉你"现在需不需要你"。

### 先说一个查出来的事实

我在 DSH 里扒了一遍当前所有界面扩展点（右侧栏可注册的位置），得到一个数字：

**右栏的 tab 位置已经有 16 个占用者**——文件、编辑器、终端、Git、子代理、计划、交付物、定时任务、浏览器、侧聊、diff、文件审阅、账本……

然后我搜了「goal」这个词。整份清单里只出现**一次**，而且是在**工具名**里（`create_goal` / `update_goal`）。

**也就是说：agent 能创建、暂停、完成一个目标；人在界面上没有任何地方能看到它，更没有任何地方能暂停它。**

不是做得不好，是**没有**。

这解释了那个"白等半小时"：agent 的自主性已经超过界面的表达能力了。

### 所以我做了个「塔台」

一个右侧栏面板，只回答四个问题，按"要不要你"排序：

**① 有几个在飞？** 四个数字：在飞 / 待处置 / 后台 / 定时。

**② 谁需要你？** 只由确定性规则产生，不是模型猜的：
目标受阻（附宿主给的受阻原因）、目标暂停、作业失败。

**③ 每个 agent 在干什么？** 一个活 agent 一张卡：工作区、模型预设、第几轮对话、跑了多久、目标原文、第 n/m 轮、是不是子代理。

**④ 你能就地做什么？**
- 目标：暂停 / 继续 / 完成
- 后台作业：终止
- 定时任务：立即执行

全是**一次点击一个动作**，没有批量，没有自动重试。

### 三个刻意的取舍

**1）不用模型做判断。**
"这个目标是不是在原地打转"这种判断，v1 之前一律不做。会误判的自动化，比没有自动化更伤信任。
待处置列表里每一条，都能追到一个宿主事实。

**2）数据一步都不出这台机器。**
不落盘、不出网、不建账号。所有数据在 Host 进程里现取现序列化，通过同源 loopback 路由给面板。
代价是没有云同步、没有多机协作；换来的是我敢把它装在任何客户机器上。

**3）动作必须带版本号。**
每个目标动作都带 `revision`，别人改过就报冲突，绝不覆盖。宁可让你多点一次，不让我猜。

顺带一个工程细节：**面板关掉就卸载**，轮询随之停止；只有入口按钮时是 9 秒一取，面板打开才 4 秒。
没有遥测，没有"顺手上报"。

### 装

```bash
dsh plugin --profile <你的profile> add dsh-plugin-tower
```

装完右栏会出现「塔台」tab；输入框工具行也有一个入口，有待处置时亮红角标。

> 首次安装立即生效。**替换版本需要重启一次** Harness（模块代机制），这点我在 README 里写明了。

### 边界（先说清，省得你踩）

- **只看活着的 agent**。会话关掉之后，目标状态目前看不到——持久快照在 session log 里，我计划在 v0.2 补只读回放。
- **没有模型判断**，所以"看起来在空转"这种状态暂时识别不了（v0.3 的静默检测）。
- **没有任何遥测**。所以我拿不到你的使用数据，功能优先级只能靠 issue 和访谈——欢迎直接骂。

### 为什么现在做这个

Agent 越强，人的瓶颈越从"怎么做"移到"要不要继续"。
界面该优化的不是给更多信息，而是**更少次决策**。

塔台只做一件事：**把"要不要继续"压缩成一次点击，把"有没有事"压缩成一个数字。**

如果你也在同时跑好几个 agent，装一下试试。有 bug 或想要的能力，直接开 issue。
