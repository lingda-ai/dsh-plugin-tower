# 塔台 · 产品方案（v0.1 → v1.5）

> 配套：`product-brief.md`（为什么是这个方向：证据链与竞品）、`business-case.md`（值不值得做：市场与钱）。
> 本文只回答一件事：**产品怎么长，每一版交付什么，怎么验收。**

---

## 1. 定义

**塔台是 DSH 里的人机交接面调度层。**
它不生产内容、不解释内容，只在**「agent 自己跑」与「人要不要继续」之间**提供一个可操作的面。

**它不是什么**（写进来是为了防止产品漂移）：

- 不是文件/预览/编辑器（生态 16 个占用者已饱和）
- 不是 token 仪表盘（账本在做，且钱是滞后指标）
- 不是会话流程图（只解释不干预）
- 不是第二个聊天窗口（增加对话次数）
- 不是告警平台（通知是手段，放行才是目的）

---

## 2. 用户与场景

| 角色 | 真实场景 | 当前代价 | 塔台给的 |
|---|---|---|---|
| 单人重度（开发者/研究者） | 3–5 个会话并行，其中一个挂 goal 自动续轮 | 轮流点左侧会话确认 | 一个数字 + 一次点击 |
| 长任务操作者 | 让 agent 跑 20 分钟构建/迁移 | 守着或反复回来看 | 不守也知道；失败立刻可见 |
| 自动化使用者 | 定时任务夜间跑 | 第二天翻结果 | 一眼看出谁成功、谁卡住 |
| 团队值班（未来） | 多人多机各自跑 | 群里问、口头同步 | 共享只读镜面 + 审计留痕 |

**一句话 JTBD**：当我放手让 agent 跑时，我要在**不打断当前工作**的前提下知道它是否健康，并在**一步之内**让它继续或停下。

## 3. 产品结构：四层能力，逐层加钱

```
L4 审计 Audit     不可篡改事件流 / 合规导出 / 留存策略        ← 企业付费点
L3 治理 Govern    策略（超时自动暂停、重试上限、预算联动）/ 团队共享镜面  ← 团队付费点
L2 提醒 Alert     本地通知 / 规则引擎 / 静默检测                ← Pro 付费点
L1 观察 Observe   全机航班 / 目标 / 作业 / 定时 + 五个动作       ← 免费，获客与信任
```

**分层原则**：L1 永不阉割。免费层必须**完整可用**，否则没人会把它变成习惯；
付费卖的是「不用一直看」（L2）、「多人一起看」（L3）、「出了事能证明」（L4）。

### L1 观察（v0.1，已交付）

- 全机航班：活 agent 一行一卡（工作区、模型预设、第 n 轮、在跑标记、子代理标记）
- 目标：阶段、第 n/m 轮、受阻原因、进度条；动作 暂停 / 继续 / 完成
- 后台作业：运行中 + 10 分钟内失败；动作 终止
- 定时航班：未结束任务的下一次执行；动作 立即执行
- 三个入口：输入框工具行（带待处置角标）、右侧栏 tab（chip 计数）、空白右栏引导页
- 验收：GET 快照覆盖 4 类数据；五个动作各一次成功 + 一次失败可见；无服务时降级为空而不是报错

### L2 提醒（v0.2–v0.3）

| 能力 | 规格 | 为什么值钱 |
|---|---|---|
| 本地系统通知 | 目标转入 blocked / 作业失败 / 目标完成 → 一条系统通知，点击回到会话 | 把「守着」变成「不用守」 |
| 静默检测 | 某会话 N 分钟无事件且处于 active goal → 标黄「可能空转」 | 比「失败」更常见、更浪费钱 |
| 规则引擎 | 声明式：`job.running > 10min` → 通知/标红；`goal.rounds > 20` → 提醒 | 每个团队的阈值不同，配置即价值 |
| 通知节流 | 同一对象 10 分钟内只提醒一次；夜间静默时段 | 不打扰是留存的关键 |

**不做**：云端推送（要出网）。通知只走本机 OS。

### L3 治理（v1.0，团队付费点）

| 能力 | 规格 |
|---|---|
| 共享只读镜面 | 一机导出「运行快照」为只读链接（局域网/文件共享），不经过任何云 |
| 策略下发 | 每项目一份 `tower.policy.json`：超时自动暂停、失败 N 次自动终止、预算联动（与账本） |
| 多人可见 | 多人订阅同一镜面；谁在跑、谁卡住，团队一张表 |
| 审计导出 | 事件流 → JSON / CSV / Markdown 报告，带 SHA-256 链 |

**关键取舍**：共享镜面是**只读快照文件**，不是实时同步服务。理由见 business-case 的「不出域」章节 ——
一旦引入同步服务，本地性护城河立刻消失，而收益只是「实时」，不值。

### L4 审计（v1.2–v1.5，企业付费点）

- append-only 事件流：`goal.phase.changed`、`job.settled`、`action.applied`（谁、何时、从哪个会话、结果）
- 哈希链 + 可校验导出包（含校验说明），满足「过程可追溯」而非「财务审计」
- 留存策略：保留天数、脱敏规则（工作区路径替换为别名）
- 离线许可：签名 license 文件校验，**不联网激活**（否则破坏本地性）

## 5. 设计原则（八条，违反即回滚）

1. **决策次数最少化**：任何新增区块都必须回答「它降低了哪一次决策」。
2. **一个动作一次点击**：不批量、不自动重试、不静默补偿。
3. **乐观并发**：所有状态变更带 `revision`，冲突就报，不覆盖。
4. **确定性优先**：v1 之前不引入模型判断；会误判的自动化比没有更伤信任。
5. **降级不崩**：任一宿主服务缺失 → 该区块空，不影响其它区块与宿主。
6. **不出域**：不落盘、不上报、不建账号；后续所有付费能力都必须满足这条。
7. **安静优先**：没事时不打扰；红灯只在真需要人时亮。
8. **可放弃**：面板关闭即卸载，不留定时器、不改宿主配置。

## 6. 状态模型与规则

### 6.1 航班状态（由宿主事实推导，不自造状态）

```
running   = turnBoundary.openTurnStartSeq != null
phase     = goal.phase ∈ {active, paused, blocked, complete} | 无目标
health    = blocked | failed-job | idle | ok   （由规则表产出）
```

### 6.2 待处置规则（v0.1，全部确定性）

| 规则 | 级别 | 来源 | 动作 |
|---|---|---|---|
| `goal.phase == blocked` | urgent | 宿主 `blockedReason` | 打开会话 / 完成 |
| `job.status == failed` 且 10 分钟内 | urgent | `jobs.list` | 打开会话 / 终止 |
| `goal.phase == paused` | waiting | — | 继续 |
| `goal.roundsStarted >= maxGoalRounds` | waiting | — | 完成 |
| 静默超时（v0.3） | waiting | 事件时间差 | 打开会话 |
| 自定义规则（v0.3） | 用户定义 | `tower.policy.json` | 通知 |

排序：urgent 在前，同级按时间新→旧；上限 20 条（超出的收敛成「还有 N 条」）。

## 7. 路线图与验收

| 版本 | 主题 | 交付 | 验收标准 | 估算 |
|---|---|---|---|---|
| v0.1 | 能看见、能按住 | 已交付 | 见 §4 | ✅ |
| v0.1.4 | 布局收敛 + 键盘 | 栅格 auto-fill（单卡不再拉满）、无目标卡「建目标」入口、状态行分隔与锚点、面板内 j/k/Enter | 单卡宽度 ≤ 约 1/3 屏；键盘不劫持输入框 | ✅ |
| v0.1.3 | 看得见失败原因 | 作业日志尾部（只读 `jobs.readAt`，不动游标、带截断标记），面板内联展开 | 点「日志」能看到失败那一行；跨会话读被拒 | ✅ |
| v0.1.2 | 界面重构 | 主题令牌、状态行、作用域、稍后处理、空态即入口、渲染边界 | 明暗主题下无硬编码色；面板异常不白屏 | ✅ |
| v0.2 | 不漏 | 已关闭会话的目标回放（session log 只读）、作业 24h 历史、`ask_user_question` 等待列表（等宿主接口） | 关闭会话后仍能看到最后目标状态 | 3–5 人日 |
| v0.3 | 提醒 | 系统通知、静默检测、规则文件、节流 | 关掉面板也能收到通知；一晚不打扰 | 5–8 人日 |
| v1.0 | 治理 | 只读镜面导出、策略下发、审计导出（哈希链） | 3 家团队连续用 2 周不丢事件 | 10–15 人日 |
| v1.2 | 审计+ | 脱敏、留存、校验工具、离线 license | 第三方按说明可独立校验导出包 | 8–12 人日 |
| v2.0 | 会判断（可选层） | LLM 摘要「目标在原地打转」、建议动作（**不自动执行**） | 误报率 < 20% 才允许默认开启 | 5–8 人日 |

**排序依据**：先确定性后概率性；先单机后多人；先动作后智能。

## 8. 指标与度量（没有遥测怎么办）

**北极星**：`每周人工放行次数`（Weekly Human Clearances）—— 它同时代表 agent 在自主干活、人在有效治理。

| 层 | 指标 | 采集方式 |
|---|---|---|
| 获取 | 月安装量、star、issue 数 | npm / Gitee / GitHub 公开数据 |
| 激活 | 首日打开塔台占比 | **可选匿名 ping（默认关）** + 访谈抽样 |
| 参与 | 周打开次数、处置率、中位处置时延 | 同上 |
| 留存 | 次周留存、4 周留存 | 同上 |
| 付费 | Pro/团队转化、企业线索数 | 订单/合同 |

**度量原则**：默认零遥测是产品承诺，所以核心指标靠**默认关闭的可选匿名统计 + 抽样访谈**，
接受「数据不全」的代价，并在对外材料里如实说明。宁可少一份报表，不偷偷上报。

## 9. 交付与质量

- **契约守卫**：所有宿主服务经 `ctx.get` 可选获取；每个动作失败原样回传原因；对 `@Remote` 契约变化做冒烟测试（现有 30 条断言即基线）。
- **兼容矩阵**：至少覆盖当前 DSH 版本 ±1 个次版本；每次宿主升级跑一遍 `test/`。
- **更新机制**：替换模块代需重启（平台限制）→ 在 README 与设置页写明，并把「无需重启的更新」列为 v0.3 技术债。
- **支持 SLA**：个人版社区支持；团队版 48h；企业版 8h（工作日）。

---

## 10. 非目标（反功能清单）

- 不做云端同步/账号体系
- 不做 token 计费/限流（账本领域）
- 不做消息内容存储（只存状态事件）
- 不做跨机自动执行（只读镜面）
- 不做「智能代管」（v2 前）
- 不接管审批/提问队列（宿主没有稳定只读接口，不猜）
