# 塔台 · Tower

[![verify](https://github.com/lingda-ai/dsh-plugin-tower/actions/workflows/verify.yml/badge.svg)](https://github.com/lingda-ai/dsh-plugin-tower/actions/workflows/verify.yml)

DSH 右侧栏的 **Agent 运行值守台**：一屏看清谁在飞、谁卡住、谁等你，并就地放行。

> 适合同时开多个会话、或用「目标 / 后台作业 / 定时任务」让 agent 自己干活的人。
> 源码：[GitHub](https://github.com/lingda-ai/dsh-plugin-tower) · [Gitee](https://gitee.com/linzhengtong/dsh-plugin-tower)

## 30 秒上手

```bash
dsh plugin --profile <你的 profile> add dsh-plugin-tower
```

装完在三个地方能找到它：

- **输入框工具行右侧**的「塔台」按钮——有待处置时亮红角标；
- **右侧栏标签**「塔台」；
- **空白右栏引导页**里的「塔台」卡片。

> 安装后立即生效；**升级**需要完全退出 App 再打开（不是刷新页面）。

## 四个常见用法

**① agent 卡在问我时，我第一时间知道。**
它调用 `ask_user_question` 的那一刻，面板顶部就会出现「在等你回答：…」，点开直接回到那个会话。

**② 让它自己跑，我随时能停。**
没有目标的航班卡上直接点 `[建目标]`，填一句「想让它继续做什么」就建好了（宿主支持时**真的创建**，
不是复制一句话）。建好后卡片上出现轮次和 `[暂停] [完成]`；目标在推进但 20 分钟没有动静时，
会被标成「可能空转」。

> 老宿主没有创建接口时，按钮会诚实地变成「复制建目标指令」，而不是假装建好了。
> `[完成]` 和 `[终止]` 都是**两段确认**：第一下只上膛，4 秒内再点才执行。

**③ 作业失败，先看日志再决定。**
后台作业行点 `[日志]` 直接看输出尾部（只读，不影响 agent 自己的读取位置），
确认后再 `[终止]` 或回会话里处理。

**④ 交接 / 汇报：一分钟出一页。**
底部「值守报告」→ 先在面板里看排版好的预览，再选形式：
`[下载 .md]` 贴进周报或交接群；`[分享 HTML]` 得到一个**单文件网页**，
对方不用装任何东西，双击就能在浏览器里看（自带浅色/深色）。**都不含任何对话内容**。

**⑤ 会话多了也不会看不过来。**
多个工作区时航班自动分组（组头可折叠，显示「3 个 · 1 待处置」），可切「待处置优先 / 最近活动 / 名称」，
也能一键「只看待处置」。选择会记在本机。

**⑥ 想留证据：开审计。**
「审计」→ `[开始记录]`。之后你点过的每个动作都会追加到
`$DSH_HOME/.dsh/tower/audit.jsonl`，每条带前一条的哈希**和操作者（`用户@主机`）**；
`[校验]` 会指出被改动的是第几条。默认关闭，关闭时连目录都不创建。
单文件超过 5MB 自动轮转成 `audit.jsonl.1`（保留一份备份），不会无限增长。

## 设置

**面板上的三个开关**（都记在本机）：

| 开关 | 作用 |
|---|---|
| 通知 | 授权后，**窗口不在前台时**弹出；只弹紧急项，6 小时内不重复；**未处理满 30 分钟会升级再提醒一次**（最多 2 次），避免紧急项静默沉底 |
| 紧凑 | 收起元信息、压缩间距，一屏能放下更多 agent |
| 折叠 | 后台/定时/历史/报告的展开状态会被记住 |

**策略文件**（可选，改完即生效，无需重启）：

```json
// $DSH_HOME/.dsh/tower/policy.json
{
  "idleMinutes": 20,
  "historyHours": 24,
  "historyLimit": 20,
  "notifyOnlyUrgent": true,
  "includeCost": true,
  "autoPause": { "enabled": false, "afterIdleMinutes": 45 }
}
```

`autoPause` **默认关闭**。开启后，只有「目标处于执行中 + 当前没在跑 + 超过阈值没有事件」才会被暂停，
且每次动作都会记进处置历史与审计（`verb=auto-pause`），不会静默改动。

**团队共享策略**（可选）：把一份 `policy.json` 放进受版本控制的仓库，用环境变量指过去：

```bash
export TOWER_POLICY=~/code/ops/.tower/policy.json
```

合并顺序是 **内置默认 ← 本机 ← 团队**：团队文件只覆盖它显式写了的键，
个人没被覆盖的偏好（比如通知开关）保持不变；嵌套对象按子键合并（`autoPause.enabled`
团队改、`afterIdleMinutes` 仍用本机）。
两个文件都解析失败时不会静默——面板页脚会出现「策略有警告」，报告里也会写明来源与失败原因。

## 数据与隐私

- 只读：除了你点击的三个动作，不改任何状态；
- 不落盘、不出网、无账号；轮询只在面板打开时进行（4s），关闭即卸载；
- 审计是**可选项**，写入位置、条数、哈希链都能在面板里看到；
- 报告只含状态与金额，**不含对话内容**。

## 已知限制

- **只显示仍然活着的 agent**。会话关掉后，要展开「已收场」才看得到它最后一次目标状态。
- **没有模型判断**：待处置全部来自确定性规则（在等回答 / 目标受阻 / 暂停 / 作业失败 / 长时间无动静）。
- **待答是推断出来的**：宿主没有「待答列表」接口，塔台从会话事件流（`tool/call` → `tool/result`）配对得出；
  宿主不派发该事件时它不会出现，其它告警不受影响。
- **升级要重启**：替换已安装版本后需完全退出 App。刷新页面只重载浏览器半。
- **成本依赖账本**：装了账本才有成本节；没装或读不到时整节不出现，不会显示 ¥0。

## 升级与卸载

```bash
# 升级
dsh plugin --profile <你的 profile> add dsh-plugin-tower@latest
# 然后完全退出 App 再打开

# 卸载
dsh plugin --profile <你的 profile> remove dsh-plugin-tower
```

## 出问题时

**先确认你跑的是哪一代**（升级后最容易踩的坑）：

```bash
curl -s http://127.0.0.1:<端口>/dsh-tower/api?counts=1 \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['version'])"
```

应与面板页脚左侧的 `v` 号一致；不一致以 Host 为准，并重启 App。

| 现象 | 先看这里 |
|---|---|
| 面板是空的 | 页脚是否有「N 项不可用」——某些宿主服务缺失会显式降级，不是坏了 |
| 「已收场」为空 | 只有带过目标的已关闭会话才会出现；这台机器从没建过目标就是空的 |
| 通知没弹 | 头部「通知」是否开启；页脚会写「权限被拒绝」或「环境不支持」 |
| 卡片显示「面板渲染失败」 | 面板自带渲染兜底，把错误行发出来即可定位 |
